# 运行维护

## 数据位置

- `.env`：实际密钥、随机初始密码、数据库连接；忽略Git。
- `data/mysql`：独立MySQL业务和测试数据库。
- `data/uploads`：导入原文；可能有敏感信息，应按实际企业权限保护。
- `data/milvus`：1024维向量索引。
- `data/bm25`：版本词法快照。
- `data/logs`：启动脚本的API/Worker/Web进程输出。
- `data/verification`：测试截图、实际检索评测。
- `D:/CodexData/caches/huggingface`：下载的Qwen权重与配置。

模型缓存、下载、包缓存和临时路径由scripts/env.ps1设置，均在D盘。不修改Windows全局临时路径，不删除旧迁移备份。

## 重启与恢复

`.\scripts\stop.ps1`仅处理由dev.ps1记录且命令行仍指向当前项目的进程。MySQL继续运行，数据不删除。再执行dev.ps1重启。

Worker宕机后，运行任务租约最多3分钟过期，之后重新领取。第三次中断转为失败，人工点击重试可重新排队。外部模型连接异常自动有限重试；配置/引用/格式错误明确失败。

Milvus集合打开和检索前显式load，支持进程重启后查询；不要另开并行脚本直接写同一向量数据库。检索评测通过API排队执行。

## 更新模型

更改LLM配置后重启API和Worker。更改Embedding模型需要匹配向量维度与重建全部知识索引；当前实现固定1024维，不支持随意替换不同维度的模型。索引元数据记录模型名，查询时检测不同模型名。

## 备份

生产使用前制定并演练备份恢复。MySQL应使用逻辑备份或一致性快照，不直接复制正在写入的InnoDB目录。上传原文、知识元数据和引用快照必须保留；向量与词法索引可重建。复制嵌入式索引前先停Worker。

本交付不自动执行数据清理/删除，不修改现有MySQL80服务，不自动配置公网监听。默认监听127.0.0.1。

## 已知规模边界

单Worker串行执行保证嵌入式索引一致性；长文档导入会让检索任务排队。适合本地演示、工程验证和小规模试点，未作企业生产容量承诺。复杂PDF表格、OCR、多租户、真实渠道、定时SLA升级和多轮客户会话是后续扩展项。

初始迁移0001使用当前ORM元数据创建表；后续修改schema时必须新增显式Alembic迁移，不得继续依赖create_all升级既有表。降级入口禁用破坏性删表。

## 独立账号与凭据轮换

四个本地账号使用 `.env` 中各自的 `ADMIN_PASSWORD`、`SUPERVISOR_PASSWORD`、`AGENT_PASSWORD`、`KNOWLEDGE_PASSWORD`。首次迁移后执行 `python scripts/secure_accounts.py`：缺少、重复或示例密码会触发四个账号的新随机密码生成；有效配置则同步到这四个固定账号。加 `--rotate` 明确轮换全部四个账号。密码只写 `.env`，不打印。脚本不管理其他人员账号，不修改订单/工单/知识数据。

本次升级已轮换原有共享密码，包括管理员；请从本地 `.env` 读取新的对应密码。JWT 绑定账户当前凭据指纹，旧格式会话及密码轮换前的会话均不能继续使用。API/Worker 更新或 `.env` 修改后重启进程；密码轮换后的再次登录使用新值。

## 测试数据库安全

本机执行 `python scripts/prepare_test_db.py`，只管理3307独立实例的 `ticketflow_tests` 账号和测试库。该账号只授予测试库权限，配置写入 `.env` 的 `TEST_DATABASE_URL`，保留现有业务/测试数据。不会继续把测试库权限授予业务账号。

外部实例需手动配置专用账号，库名须为 `*_test` 或 `*_test_*`，不同于业务库；账号须不同于业务账号且非 root。GRANT 的数据库名模式要转义 `_`，如 `` `ticketflow\_test`.* ``，不允许 `WITH GRANT OPTION`、全局权限、其他库权限、角色或代理授权。连接查询参数目前仅允许 `charset`。测试启动在建表前校验 URL、缓存引擎目标及有效授权，失败即停止，不自动改写配置或回退业务库。

## 上传入口的网络部署

应用自身在 multipart 解析前完成 Bearer/JWT、凭据指纹和知识角色校验，再按实际收到的字节计数。默认总请求上限10 MiB + 64 KiB，仍保留原文件10 MiB上限；缺少/伪造 Content-Length、分块传输不能绕过实际字节预算。无效/重复长度头被拒绝。接收期限默认30秒，慢传输返回408；请求及后台鉴权线程分别设置并发上限，满载返回429。取消/超时不会释放尚在运行的鉴权线程容量；线程结束后释放，数据库连接、读取和写入各有10秒 socket 超时。

临时缓存前64 KiB使用内存，之后写入进程 TEMP/TMP（启动脚本设置在D盘），请求结束、拒绝、断开或取消后关闭并清理临时文件。已有数据文件和迁移备份不会被清理。API 多进程部署时上述容量按进程计，总预算须乘以进程数。

反向代理也应限制请求体、连接数和等待时间。Nginx 的上传 location 可参考以下片段，实际站点的 TLS、前端静态文件和认证体系需按环境配置；本项目未安装或声称验证外部代理部署：

```nginx
location = /api/v1/knowledge/documents {
    client_max_body_size 10304k;
    client_body_timeout 30s;
    proxy_request_buffering off;
    proxy_http_version 1.1;
    proxy_pass http://127.0.0.1:8000;
}
```

将等效限制覆盖尾随斜杠等代理转发路径，并在 http/server 级配置客户端连接/速率和请求头超时。代理的 `client_body_timeout` 是读取间隔限制，应用仍负责总接收期限。当前修复范围是上传入口资源预算；PDF 解压/展开后配额、登录及模型调用费用配额等仍是报告中的独立中危事项。
